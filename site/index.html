What it does, in plain words

Many systems receive things that someone must look at first. A resident reports a closed road. A new issue arrives. A deployment seems stuck. Often the case is clear, and the system can act at once. Sometimes it is not clear, and a person should check it. Pointsman makes this first call, and it keeps a record of every call.

  1. It asks fixed questions

    Example: a resident reports a fallen tree on a road. What kind of closure is it? Could someone be in danger? An AI answers each question and says how sure it is, for example "danger: yes, 85 %".

  2. People's rules decide

    People write the rules, for example: "danger 70 % or more: urgent". The AI does not decide alone. The rules can also use facts from public data, for example whether the place is in a flood zone.

  3. It answers, and keeps a record

    The answer is an action, here "urgent". Pointsman saves the questions, the answers and the rule that it used. A person can correct the answers later. So you can see how often the AI was right.

Decisions you can check

Many systems make small routing decisions all day: which team, how urgent, wait or stop. Pointsman makes them in one place, the same way every time, and keeps a record you can measure.

Typed questions

Yes/no, choice and score questions. Every answer comes with its probability, so you know how sure the model is.

Policy, not prompts

Rules like team.p >= 0.85 turn answers into an action. The policy is plain config, checked when it is loaded, never evaluated as code.

A person when unsure

Below your threshold the action is review. The decision waits in a review queue, and the final answer is sent back, signed, to your callback.

Versioned profiles

Questions and policy live in YAML profiles with a JSON Schema, validated in CI. Each decision records the profile version and the model.

Feedback and accuracy

People correct decisions; corrections are logged next to the answers. Measure how often each profile version was right before you raise its thresholds.

Any model

Models plug in through adapters. Today: Workers AI models through Cloudflare AI Gateway, and a mock model for development and tests.

How it works

One request in, one decision out. The decision log keeps everything needed to explain it later.

  1. Send a state

    Your system posts what it knows: an issue, a deploy event, a form. As JSON or text, to a profile.

  2. Ask the questions

    The profile's model answers its typed questions. If it fails, a fallback model takes over.

  3. Apply the policy

    The rules compare answers and probabilities. The first rule that matches picks the action.

  4. Act

    Your system follows the action, or a person decides.

Profiles are config

A profile says what to ask and what to do with the answers. Change a threshold with a pull request, not a prompt.

  • Reviewed like code. Profiles live in your own private config repository and are published on deploy, write-once per version.
  • Validated before they run. A JSON Schema and a validator check every profile in CI.
  • Visible where you want. A profile can be offered to agents through MCP, or kept to the API.

Profile format

profiles/issue-triage.yamlYAML
id: issue-triage
version: 1
model: clef-flash
fallback_models: [clef]
questions:
  - name: team
    type: choice
    instructions: Which team should handle this issue?
    criteria:
      - { value: backend,  description: "APIs, databases" }
      - { value: frontend, description: "Web pages, styles" }
      - { value: docs,     description: "Documentation" }
  - name: urgent
    type: noul
    instructions: Does this block someone's work today?
policy:
  rules:
    - when: "team.p >= 0.85"
      action: auto
  default: review

MCP for agents

Add Pointsman as a connector, and agents call decide instead of guessing. Machines use API tokens; people log in with GitHub and can correct decisions.

GitHub issue triage

A GitHub Action labels new issues from a decision, using only the labels you list. When Pointsman is not sure, the issue gets a "needs triage" label instead.

FIWARE bridge

FIWARE is open-source software for smart-city data platforms. It uses an open data standard, NGSI-LD. The bridge connects such a platform to Pointsman. When data changes, the bridge asks Pointsman. Then it writes the decision back to the platform, so that other apps can use it.

Get started

Run it locally in a few minutes, with the example profiles and a mock model. No Cloudflare account needed.

  1. Install

    Node.js 24 and pnpm.

  2. Start the Worker

    A local decision log, then the Worker on port 8787.

  3. Ask for a decision

    Create a local API token and send a state to a profile.

  4. Deploy your own

    Copy the config repository template: your profiles, your Cloudflare account, private.

    docs/deployment.md →
terminalsh
# 1. install
git clone https://github.com/geolonia/pointsman
cd pointsman
pnpm install

# 2. start
pnpm db:migrate:local
pnpm dev

# 3. ask (in a second terminal)
node scripts/tokens.mjs create \
  --client demo --profiles issue-triage --local
export POINTSMAN_TOKEN=pm_…
curl -s localhost:8787/v1/decide/issue-triage \
  -H "authorization: Bearer $POINTSMAN_TOKEN" \
  -H 'content-type: application/json' \
  -d '{"state": {"issue": {"title": "Login page is blank"}}}'
