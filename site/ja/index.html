確かめられる判定

多くのシステムは、どのチームに回すか、急ぎかどうか、待つか止めるか、といった小さな判断を一日中しています。Pointsman はそれを一か所で、毎回同じやり方で行い、あとで測れる記録を残します。

型のある質問

はい／いいえ、選択、スコアの質問です。どの答えにも確率が付くので、モデルがどれだけ確信しているかが分かります。

プロンプトではなくポリシー

team.p >= 0.85 のようなルールで、答えをアクションに変えます。ポリシーはただの設定で、読み込むときに検査され、コードとして実行されることはありません。

迷ったら人へ

しきい値に届かなければ、アクションは review です。判定はレビュー待ちの一覧に入り、最終的な答えは署名付きでコールバック先に送られます。

バージョン付きのプロファイル

質問とポリシーは YAML のプロファイルに書き、JSON Schema で CI が検証します。判定ごとに、プロファイルのバージョンとモデルが記録されます。

フィードバックと正解率

人が判定を訂正すると、その訂正が答えの横に記録されます。しきい値を上げる前に、プロファイルのバージョンごとの正解率を測れます。

モデルを選ばない

モデルはアダプターでつなぎます。いまは Cloudflare AI Gateway 経由の Workers AI のモデルと、開発とテスト用のモックモデルが使えます。

仕組み

リクエスト 1 つに、判定 1 つ。あとで理由を説明するのに必要なものは、すべて判定ログに残ります。

  1. 状態を送る

    システムが分かっていること（Issue、デプロイのイベント、フォームなど）を、JSON かテキストでプロファイルに送ります。

  2. 質問に答える

    プロファイルのモデルが、型のある質問に答えます。失敗したときは予備のモデルが引き継ぎます。

  3. ポリシーを当てる

    ルールが答えと確率を比べます。最初に当てはまったルールがアクションを決めます。

  4. 動く

    システムはアクションに従います。または人が決めます。

    autoreview独自のアクション

プロファイルは設定です

プロファイルには、何を聞き、答えをどう使うかを書きます。しきい値はプロンプトではなく、プルリクエストで変えます。

  • コードと同じようにレビュー。プロファイルは自分たちの非公開の設定リポジトリに置き、デプロイ時に公開されます。同じバージョンは一度しか書き込めません。
  • 動かす前に検証。JSON Schema と検証ツールが、CI ですべてのプロファイルを確認します。
  • 見せる場所を選べる。MCP でエージェントに見せることも、API だけに限ることもできます。

プロファイルの形式（英語）

profiles/issue-triage.yamlYAML
id: issue-triage
version: 1
model: clef-flash
fallback_models: [clef]
questions:
  - name: team
    type: choice
    instructions: Which team should handle this issue?
    criteria:
      - { value: backend,  description: "APIs, databases" }
      - { value: frontend, description: "Web pages, styles" }
      - { value: docs,     description: "Documentation" }
  - name: urgent
    type: noul
    instructions: Does this block someone's work today?
policy:
  rules:
    - when: "team.p >= 0.85"
      action: auto
  default: review

はじめる

サンプルのプロファイルとモックモデルを使えば、数分で手元で動かせます。Cloudflare のアカウントは要りません。

  1. インストール

    Node.js 24 と pnpm が必要です。

  2. Worker を起動

    手元の判定ログを作り、ポート 8787 で Worker を起動します。

  3. 判定を頼む

    手元用の API トークンを作り、プロファイルに状態を送ります。

  4. 自分たちの環境にデプロイ

    設定リポジトリのテンプレートをコピーします。プロファイルも Cloudflare アカウントも自分たちのもので、非公開のままです。

    docs/deployment.md（英語）→
ターミナルsh
# 1. インストール
git clone https://github.com/geolonia/pointsman
cd pointsman
pnpm install

# 2. 起動
pnpm db:migrate:local
pnpm dev

# 3. 判定を頼む（別のターミナルで）
node scripts/tokens.mjs create \
  --client demo --profiles issue-triage --local
export POINTSMAN_TOKEN=pm_…
curl -s localhost:8787/v1/decide/issue-triage \
  -H "authorization: Bearer $POINTSMAN_TOKEN" \
  -H 'content-type: application/json' \
  -d '{"state": {"issue": {"title": "ログイン画面が真っ白"}}}'

Pointsman はまだ初期の試作段階です。PoC マイルストーンで進み具合を確認できます。試したら、ぜひ Issue で教えてください。ドキュメントは英語です。
