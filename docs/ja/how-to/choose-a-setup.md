## 自分のコンピューターで試す

Pointsman は、自分のコンピューターで、どの質問にも同じ決まった回答を返すモックの AI モデルを使って動かせます。API トークンはコマンド 1 つで作れて、自分のコンピューターの中だけで使えます。[はじめてのプロファイル](../tutorials/first-profile.md)は 15 分ほどかかります。

## すでに動いている Pointsman を使う

動かしている人に、次の 2 つを頼みます。

- その Pointsman の **URL**。
- 自分のクライアント用の **API トークン**。トークンが使えるプロファイルは限られるので、どのプロファイルが必要かを伝えます。

プロファイルは、ふつうは動かしている人の非公開の設定リポジトリにあります。追加や変更は、その人に頼むか、そのリポジトリにプルリクエストを送ります。その前に、チュートリアルと同じように、自分のコンピューターでプロファイルを書いて確かめておきます。

AI エージェントからも Pointsman を使えます。[AI とエージェント](../about/ai.md)を見てください。

## 自分で動かす

デプロイは、テンプレートから作る非公開の GitHub リポジトリ(設定リポジトリ)で設定します。このリポジトリには、プロファイルと、使う Pointsman のバージョンを置きます。`main` にプッシュするたびに、GitHub Actions が自分の Cloudflare のアカウントにデプロイします。AI には同じアカウントの Workers AI を使うので、ほかの AI サービスのキーは要りません。

手順は[Pointsman をデプロイする](../../deployment.md)にあります。

<details><summary>デプロイに必要なものの一覧</summary>

- **Cloudflare のアカウント**。Pointsman はプロファイル、トークン、判定ログをここに保存し、ここで Workers AI を呼び出します。
- [`template/config-repo`](../../../template/config-repo/)(英語)から作る**非公開の GitHub リポジトリ**。
- そのリポジトリの **2 つのシークレット**: Workers、KV、D1 を編集できる Cloudflare の API トークンと、Cloudflare のアカウント ID。
- 任意で **AI Gateway**。AI の呼び出しのログと制限に使います。[モデル](../../models.md)(英語)のとおりに作るか、設定から `AI_GATEWAY_ID` を消します。

</details>

## FIWARE のプラットフォームとつなぐ

FIWARE のプラットフォームは、データを GeonicDB などの*コンテキストブローカー*に保存します。FIWARE ブリッジは、このブローカーを Pointsman とつなぎます。エンティティ(道路の報告などのレコード)が変わるとブローカーがブリッジに知らせ、ブリッジが Pointsman に判定を依頼し、判定をエンティティに書き戻します。

ブリッジは小さな Cloudflare Worker です。動いている Pointsman と、ブローカーへのアクセスが必要です。設定とサブスクリプションは[FIWARE ブリッジ](../../../bridge/README.md)(英語)にあります。

<details><summary>ブリッジに必要なものの一覧</summary>

- **動いている Pointsman**(自分のもの、または使わせてもらえるもの)と、ブリッジのプロファイルだけに使えるブリッジ用の API トークン。
- ブリッジを動かす **Cloudflare のアカウント**。Pointsman の Worker の中で動かすこともできます。
- ブローカーの **URL** と、ブローカーに複数の**テナント**(ブローカーの中で分かれたデータの場所)があればそのテナント。
- ブローカーが求める場合は、その **API キーまたはトークン**(GeonicDB は API キーを使います)。
- 自分で決める**共有シークレット**。ブローカーのサブスクリプションがこれを送り、ブリッジはこれのない通知を受け付けません。
- **ルート**: エンティティの種類ごとに、判定するプロファイル、プロファイルが読む属性、結果を書く場所。

</details>
