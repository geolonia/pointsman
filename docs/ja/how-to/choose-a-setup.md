## 自分のコンピューターで試す

Pointsman は、自分のコンピューターで、決まった回答を返すモックの AI モデルを使って動かせます。API トークンはコマンド 1 つで作れて、自分のコンピューターの中だけで使えます。[はじめてのプロファイル](../tutorials/first-profile.md)は 15 分ほどかかります。

## すでに動いている Pointsman を使う

動かしている人に、次の 2 つを頼みます。

- その Pointsman の **URL**。
- 自分のクライアント用の **API トークン**。トークンが使えるプロファイルは限られるので、どのプロファイルが必要かを伝えます。

プロファイルは、動かしている人の非公開の設定リポジトリにあります。追加や変更は、その人に頼むか、そのリポジトリにプルリクエストを送ります。その前に、チュートリアルと同じように、自分のコンピューターでプロファイルを書いて確かめておきます。

AI エージェントからも Pointsman を使えます。[AI とエージェント](../about/ai.md)を見てください。

## 自分で動かす

Pointsman のデプロイは、テンプレートから作る非公開の Git リポジトリ(設定リポジトリ)です。Pointsman のバージョンを 1 つに固定し、プロファイルを持ちます。GitHub Actions が、自分の Cloudflare のアカウントにデプロイします。必要なものは次のとおりです。

- **Cloudflare のアカウント**。プロファイル、トークン、判定ログをここに保存します。
- デプロイに使う **Cloudflare の API トークン**。リポジトリのシークレットにします。
- **AI モデル**。既定では同じ Cloudflare のアカウントの Workers AI を使うので、ほかのキーは要りません。

手順は[Pointsman をデプロイする](../../deployment.md)にあります。

## FIWARE のプラットフォームとつなぐ

FIWARE ブリッジは、GeonicDB などの NGSI-LD のコンテキストブローカーを Pointsman とつなぎます。エンティティが変わるとブローカーがブリッジに知らせ、ブリッジが Pointsman に判定を依頼し、判定をエンティティに書き戻します。必要なものは次のとおりです。

- 動いている **Pointsman**(自分のもの、またはトークンをもらったもの)と、ブリッジ用の API トークン。
- ブローカーの **URL** と、ブローカーに複数のテナントがあればその **テナント**。
- ブローカーが求める場合は、その **API キーまたはトークン**(GeonicDB は API キーを使います)。

設定とサブスクリプションは[FIWARE ブリッジ](../../../bridge/README.md)(英語)にあります。
